# 14 系统设计与模拟面试评分

## 1. 20 分钟设计骨架

| 时间 | 内容 | 必答问题 |
|---|---|---|
| 0–3 min | 澄清需求 | 哪类任务、数据敏感性、用户/租户、延迟/成本目标、危险操作？ |
| 3–6 min | 主链路 | 哪些固定 Workflow，哪里需要 Agent；为什么单 Agent 足够/不足？ |
| 6–10 min | 数据与状态 | run/step/event/approval、消息/索引、主存储/缓存、ID 与归属 |
| 10–14 min | 失败与恢复 | 超时、重试、cancel、断流、checkpoint、副作用未知结果 |
| 14–17 min | 质量与安全 | baseline/holdout、独立验证、注入、沙箱、操作审计 |
| 17–20 min | 容量与取舍 | 估算、瓶颈、背压、扩容、降级、当前方案限制 |

## 2. 容量题要会算什么

假设到达率 λ=2 个任务/秒、平均活跃执行 W=15 秒，稳定情况下平均在途约 `L=λW=30`。
这是教学假设，不是现有项目实测；排队不稳定或分布复杂时不能直接推断 P95。
接着估每个 run 的模型调用次数、token、并发 slot、数据库连接持有时间、沙箱内存。
多进程连接预算=`实例数×进程数×pool_max`；进程内 semaphore 也会乘实例数，不能声称全局限额。
优化先看分段时间，不因 LLM 慢就盲目扩大数据库池。

## 3. 三道场景题

### 企业知识助手

语料解析/增量版本 → trusted ACL → hybrid retrieval → context → answer/citation → eval。
重点追问无答案、过期知识、过滤是否覆盖 BM25、索引与模型版本、缓存 tenant key。
用 10 的源码边界作反例说明「metadata 存了」不等于「隔离完成」。

### 十分钟 Agent 长任务

API 返回 run_id → 独立 executor/queue → run/step/event 持久化 → SSE/轮询 → 审批 → resume/cancel。
重点追问创建与入队一致性、重复投递、worker crash、过期 lease、副作用结果不明、审批权限。
不要只回答「上 Redis」；明确原子 claim、状态 CAS、外部动作幂等键和可重放事件。

### Coding Agent

仓库允许名单 → disposable workspace → bounded context → 单 Agent → patch → sandbox test → 有界 repair → diff/报告。
验证服务拥有独立测试与结果判定，Agent 不能改它；模型密钥只在 orchestrator。
允许 shell=False 的 Python 测试也能执行任意代码，因此需容器/网络/资源隔离。
重点追问路径/symlink、dirty tree、patch 部分失败、超时杀进程树、恢复时文件版本不一致。

## 4. 核心取舍清单

- 单 Agent vs 多 Agent：先看任务是否真可分工与并行，再测协调成本；不要为了框架名称增加角色。
- 手写 loop vs LangGraph：前者易理解并有助现场编码，后者提供图与持久化；框架不能替你保证副作用幂等。
- SQLite vs PostgreSQL：单机 demo 简单；多实例/锁/并发需求增大后用服务型存储；不笼统称 SQLite 不能并发。
- SSE vs WebSocket：按单向事件/双向协作选择；传输断开不能自动结束业务 run。
- 缓存一致性：Cache Aside 降低读开销但有失效失败和旧读回填竞态；TTL 只是最终修复窗口。
- Docker vs 强隔离：容器降低风险但共享内核；非 root、cap drop、只读根、无 socket/secret、禁网与资源限制是基础。

## 5. 每周两次模拟

第一场：5 分钟项目自述 + 15 分钟源码追问 + 30 分钟编码 + 10 分钟反馈。
第二场：20 分钟系统设计 + 15 分钟知识问答 + 15 分钟真实经历 + 10 分钟反馈。
录音/文字记录只保存自己的练习，标记含糊、答非所问、没有数据、错把模块当主链路。

每项 0–3 分：0 不会，1 概念，2 能解释与举源码证据，3 能独立实现/验证并讲限制。

| 维度 | 训练目标 | 当前分 |
|---|---|---|
| Python/JS 与算法 | 2，核心工程题争取 3 | 待测 |
| LLM/工具/上下文 | 2–3 | 待测 |
| RAG/评测 | 2–3 | 待测 |
| 原项目源码与归属安全 | 3 | 待测 |
| 后端/状态/恢复 | 2 | 待测 |
| 前端交付/流式交互 | 2 | 待测 |
| 系统设计/容量/取舍 | 2 | 待测 |
| 真实经历/个人贡献 | 2–3 | 待测 |

这些是自我训练门槛，不是大厂面试打分标准。P0 安全或源码事实答错时优先纠正，
即使总分不错也不能称生产能力达标。
